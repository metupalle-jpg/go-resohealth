| URL Path | Data Fetched | Firestore Collections | Components Rendered |
|---|---|---|---|
| `/` | None (static shell) | None | `layout.tsx` root layout |
| `/mydata` (inferred) | Documents, Insights, Health Score | `health_documents`, `user_insights` | MyData dashboard components |

**Note:** The app currently uses Next.js App Router. Only `src/app/page.tsx` and `src/app/layout.tsx` exist as committed files. The MyData functionality is implemented as a pure API client (`src/lib/mydata-api.ts`) pointing to a **separate microservice** at `https://mydata-api.resohealth.life` — meaning go-resohealth itself is already partially headless.

| Method | Path | Request | Response | Auth |

## Auth Flow

- **Token storage:** `localStorage.getItem('reso_auth_token')` — Bearer JWT set by the auth flow
- **Token forwarding:** All API calls in `mydata-api.ts` add `Authorization: Bearer <token>` header automatically
- **Auth provider:** Firebase Auth (inferred from project structure and standard Resohealth stack)
- **User data:** Stored in Firebase Auth + Firestore `users` collection (not yet committed to this repo)
- **Membership tiers:** Not yet enforced in committed code — planned for Phase 2A

## Recommended API Surface

The following endpoints should be built in `src/app/api/` to expose go-resohealth as a headless backend for letsgo:

### `/api/wellness`
- `GET /api/wellness/categories` — List wellness treatment categories
  - Response: `{categories: [{id, name, icon, description, treatments[]}]}`
  - Firestore: `wellness_categories`
- `GET /api/wellness/treatments/:id` — Get treatment details
  - Response: `{id, name, category, price_range, duration, providers[]}`
  - Firestore: `wellness_treatments`

### `/api/destinations`
- `GET /api/destinations` — List wellness retreat destinations
  - Query: `?country=&category=&priceMax=`
  - Response: `{destinations: [{id, name, country, city, image, price_from, tags[], rating}]}`
  - Firestore: `destinations`
- `GET /api/destinations/:id` — Destination detail + availability
  - Response: `{destination, packages[], availability}`
  - Firestore: `destinations`, `booking_slots`

### `/api/bio-age`
- `POST /api/bio-age/assessment` — Submit bio-age assessment answers
  - Request: `{userId, answers: {sleep, diet, exercise, stress, ...}}`
  - Response: `{bioAge: number, calendarAge: number, delta: number, insights[]}`
  - Firestore: `bio_age_assessments`
- `GET /api/bio-age/history/:userId` — Bio-age trend over time
  - Response: `{history: [{date, bioAge, calendarAge}[]]}`
  - Firestore: `bio_age_assessments`

### `/api/membership`
- `GET /api/membership/tiers` — List membership plans
  - Response: `{tiers: [{id, name, price, interval, features[], stripe_price_id}]}`
  - Firestore: `membership_tiers`
- `GET /api/membership/status/:userId` — Get user's current membership
  - Response: `{tier, status, renewalDate, features[]}`
  - Firestore: `user_memberships`
- `POST /api/membership/subscribe` — Create Stripe checkout session
  - Request: `{userId, tierId}`
  - Response: `{checkoutUrl}`

### `/api/bookings`
- `POST /api/bookings/create` — Create a booking
  - Request: `{userId, destinationId, packageId, startDate, endDate, guests}`
  - Response: `{bookingId, status, confirmationCode}`
  - Firestore: `bookings`
- `GET /api/bookings/user/:userId` — Get user's bookings
  - Response: `{bookings: [{id, destination, dates, status, ...}]}`
  - Firestore: `bookings`

### `/api/lifesocial`
- `GET /api/lifesocial/feed` — Community wellness feed
  - Query: `?limit=20&after=cursor`
  - Response: `{posts: [{id, author, content, likes, comments, createdAt}]}`
  - Firestore: `lifesocial_posts`
- `POST /api/lifesocial/post` — Create a post
  - Request: `{userId, content, mediaUrl?, tags[]}`
  - Response: `{post}`
  - Firestore: `lifesocial_posts`

### `/api/health-records`
- Delegates to existing mydata-api microservice (already implemented)
- Proxy endpoints: `GET /api/health-records/documents`, `POST /api/health-records/upload`
- See `src/lib/mydata-api.ts` for full surface

### `/api/auth`
- `POST /api/auth/verify-token` — Verify Firebase ID token, return user profile
  - Request: `{idToken: string}`
  - Response: `{uid, email, displayName, membershipTier, isNewUser}`
  - Firestore: `users`
- `PATCH /api/auth/profile` — Update user profile
  - Request: `{displayName, avatar, preferences}`
  - Response: `{user}`
  - Firestore: `users`

### CORS Configuration
Add to all API routes:
```typescript
const ALLOWED_ORIGINS = [
  'https://resohealth.life',
  'https://go.resohealth.life',
  process.env.NODE_ENV === 'development' ? 'http://localhost:3000' : ''
].filter(Boolean);

headers.set('Access-Control-Allow-Origin', req.headers.get('origin') ?? '');
headers.set('Access-Control-Allow-Credentials', 'true');
headers.set('Access-Control-Allow-Methods', 'GET, POST, PATCH, DELETE, OPTIONS');
headers.set('Access-Control-Allow-Headers', 'Authorization, Content-Type');
```
